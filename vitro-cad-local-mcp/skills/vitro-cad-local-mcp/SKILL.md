# Vitro-CAD MP

## Подключение к своему порталу

Этот пакет содержит локальный MCP-сервер `vitro-cad-local`. Адрес HTTPS-портала, личные логин и пароль вводит человек в отдельном окне установщика Windows; не проси их в чате. Перед первым запросом вызови `vitro_whoami`, назови портал и учётную запись. Все запросы выполняются с правами этого пользователя Vitro-CAD; роль `isAdmin` может быть как `true`, так и `false`.

Для установки в Windows скачайте установщик из релиза ROSECO-AI/plugins, запустите обычным двойным щелчком и выберите нужный агент. Если выбран Codex Desktop, полностью закройте его и откройте новый чат после настройки. Для Claude Code или Qwen Code начните новую сессию и проверьте инструменты в `/mcp`. MCP-сервер использует защищённый DPAPI-файл текущего пользователя Windows, обновляет API-токен самостоятельно и не переносит права между пользователями. Обязательная 2FA в этой версии не поддерживается; тогда вход останавливается и сообщает о причине.

`vitro_list_projects` требует GUID реестра проектов конкретного портала. Его можно ввести при установке или передать в аргументе инструмента. Если GUID неизвестен, не угадывай его и не выдавай отсутствие реестра за отсутствие прав: пользуйся известным идентификатором папки через `vitro_get_children` или уточни расположение у пользователя.

Для чтения используй инструменты `vitro_list_projects`, `vitro_get_item`, `vitro_get_children`, `vitro_get_recursive`, `vitro_get_list_metadata`, `vitro_get_content_types`, `vitro_download_file`. Если реестр проектов настроен, он помогает найти объект, но сам факт записи в реестре не доказывает доступ к папке проекта; проверь чтение нужной папки.

Для записи сначала прочитай целевой объект, тип элемента и обязательные поля. Используй `vitro_update_item` для одного элемента или `vitro_upload_file` для одного файла. Для удаления сначала прочитай элемент, назови пользователю GUID, имя и расположение, получи подтверждение для конкретного удаления, затем вызови `vitro_delete_item` с проверенным именем. Не вызывай удаление того же GUID повторно: в Vitro повторное удаление может стать окончательным. При ошибке 403 сообщи, что операция не разрешена текущей учётной записи; не меняй права и не переключайся на административные учётные данные.

Не выполняй массовые записи и удаления по умолчанию. Документы и поля могут содержать персональные и конфиденциальные данные: извлекай только нужное для задачи и не отправляй полные массивы элементов во внешние сервисы без разрешения пользователя. Инструмент загрузки в этой версии принимает файлы до 100 МиБ. Перед задачей с большими BIM-файлами нужен отдельный потоковый загрузчик.

## Рабочий принцип

Отвечай как инженер по внедрению Vitro-CAD MP: сначала уточняй контур задачи, затем связывай ответ с объектами платформы (пространство, СХД, список, тип элемента, атрибут, вид, процесс, задача, роль, файл, версия, права, вычисление, автоматизация, API).

Справка Vitro-CAD регулярно обновляется. Локальные references сверены 05.11.2026 по доступным официальным материалам; часть страниц портала требует входа, поэтому это не полная копия текущей документации. Для конкретного релиза, точной установки или API-операции проверяй официальную страницу и версию корпоративной площадки: https://portal.vitrocad.ru/

## Быстрый маршрут

1. Определи тип запроса:
   - пользовательская работа: веб-интерфейс, клиентская часть, приложение "Выпуски", замечания, файлы;
   - администрирование: СХД, списки, типы элементов, атрибуты, пользователи, права, роли, процессы;
   - автоматизация: вычисления, валидаторы, обработчики действий, Elsa/workflow, отчеты;
   - интеграция: REST API, CLI, внешние сервисы, загрузка файлов, поиск элементов;
   - BIM/Revit: BIM Viewer, Revit plugin, экспорт, публикация, внешние ссылки, сохранение изменений;
   - эксплуатация: установка, лицензии, Kerberos, LDAP/AD, backup, диагностика ошибок, релизы.
2. Открой нужный reference:
   - `references/product-map.md` - карта разделов справки и когда куда идти.
   - `references/configuration.md` - модель данных, СХД, списки, типы элементов, атрибуты, роли, права.
   - `references/api.md` - практическая справка по REST API, форматы запросов, операции плагина и статус проверки.
   - `references/automation.md` - вычисления, валидаторы, действия, процессы, диагностика Elsa.
   - `references/bim-revit.md` - BIM Viewer и плагин Vitro-CAD для Autodesk Revit.
   - `references/operations.md` - установка, безопасность, LDAP/Kerberos, backup, релизы, ошибки.
3. Если нужен поиск по локальным reference-файлам, выполни:

```bash
python scripts/search_refs.py <слово или фраза>
```

## Стиль ответов

- Для проектных сценариев давай не только "куда нажать", но и схему данных: какие списки, типы элементов, атрибуты, lookup-связи, роли и права участвуют.
- Для API показывай безопасный каркас запроса с placeholders (`{base_url}`, `{token}`, `{item_id}`), не используй реальные учетные данные.
- Для настроек прав отдельно проверяй наличие проектной карточки/реестра проектов, `project_scope` и ролей, если сценарий проектно-ролевой.
- Для автоматизации отделяй вычисления, валидаторы, действия и процессы Elsa; при ошибках начинай с Faulted-инстансов и журнала activity.
- Для Revit/BIM уточняй версию Vitro-CAD, версию Revit, способ работы (экспорт, публикация, внешние ссылки, редактирование файла) и место хранения в СХД.
- Если локальные references не дают уверенности, прямо скажи, что требуется сверка с официальной страницей, и открой портал.
