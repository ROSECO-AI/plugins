# Автоматизация, вычисления и диагностика

Сверено 05.11.2026 с доступным описанием [«Автоматизация»](https://portal.vitrocad.ru/pages/viewpage.action?pageId=23659434) и материалами релизов. Некоторые страницы портала требуют входа; приведённые формулы и маршруты диагностики проверяй на версии конкретной площадки.

## Разделы автоматизации

В Vitro-CAD MP автоматизация может включать:

- вычисления на типах элементов;
- счетчики;
- валидаторы;
- условия видимости и доступности;
- действия;
- процессы и задачи;
- вызовы REST-сервисов;
- обработчики действий;
- Elsa/workflow-инстансы.

Официальная страница определяет правило автоматизации как сочетание триггера, условия и действия для типа элемента. В актуальных материалах также описана настройка автоматизации шаблонов процессов через канбан; её наличие зависит от версии площадки.

## Вычисления и формулы

Формулы строятся из функций и операторов. Имена функций начинаются с заглавной буквы. `if` - оператор ветвления и пишется с маленькой буквы.

Практический подход:

1. Назови целевой тип элемента и атрибут.
2. Определи контекст вычисления: текущий элемент, родитель, связанный элемент, вложение процесса, задача.
3. Проверь internalName атрибутов.
4. Для lookup-цепочек явно укажи, где берется объект, а где значение поля.
5. Для сложных формул предложи промежуточные вычисления или отладку через отдельный тестовый атрибут.

Пример проектной формулы из справки для карточки проекта на процессе:

```text
Field(Parent(Ref("Вложение процесса"), "Проект", true), "Карточка проекта")
```

Пример переноса карточки проекта на задачу:

```text
This("Процесс.Карточка проекта")
```

## Счетчики

Счетчики используются для автоматической нумерации элементов через сервис вычислений. Для ответа по счетчику проверь:

- какой тип элемента нумеруется;
- какой атрибут заполняется;
- какая логика нужна для префикса, года, стадии, проекта или сквозной нумерации;
- где создается счетчик в настройках пространства;
- какие вычисления запускают заполнение.

## Валидаторы

Валидаторы стоит рассматривать как отдельный слой контроля качества данных:

- обязательность по условию;
- запрет перехода статуса;
- контроль заполнения связанного поля;
- контроль загрузки файлов/версий;
- проверка маршрута процесса.

В ответах разделяй UI-обязательность поля и серверную бизнес-валидацию.

## Действия и REST-сервисы

Для действия с вызовом REST-сервиса собери:

- событие запуска;
- контекст элемента;
- URL и метод внешнего сервиса;
- маппинг полей Vitro-CAD в payload;
- обработку ответа;
- поведение при ошибке и повторном запуске;
- аудит и диагностику.

Не советуй писать секреты в открытом виде. Предлагай хранить credentials в защищенной конфигурации площадки или внешнего сервиса.

## Диагностика ошибок

Рекомендованный порядок:

1. Определи модуль сбоя: процессы, подписание, действие, вычисление, файл, доступ, BIM Viewer и т.д.
2. Проверь профильную статью справки по модулю.
3. Если ошибка в автоматизации, открой Elsa по адресу вида:

```text
https://{адрес-площадки}/workflow/manager/workflow-instances
```

4. Найди процессы со статусом `Faulted`.
5. Открой проблемный instance по GUID.
6. Выбери activity с ошибкой.
7. В панели справа открой `Journal`.
8. Изучи `Exception`, `Exception Details`, особенно `InnerException`.
9. Если в Elsa все зеленое, ищи ошибку в "Аудите запросов".

В финальном ответе по диагностике всегда проси конкретику: время ошибки, пользователь, ID элемента/процесса, действие, expected/actual, скрин или текст exception.
