# Эксплуатация, безопасность и релизы

Сверено 05.11.2026 по доступному [официальному порталу документации](https://portal.vitrocad.ru/) и по доступному индексированному описанию [входа через API](https://portal.vitrocad.ru/pages/viewpage.action?pageId=105185465). Часть административных страниц требует входа. Версия корпоративной инсталляции отдельно не установлена.

## Установка и запуск

В справке есть отдельные материалы по:

- быстрому запуску системы без настройки;
- установке компонентов системы;
- порядку установки серверной части Windows;
- порядку установки серверной части Linux;
- лицензиям;
- резервному копированию и восстановлению данных.

Для инструкций установки всегда проверяй официальную страницу под фактическую версию площадки: в 2026 году материалы установки продолжали обновляться.

## Аутентификация и каталоги

В справке есть материалы по:

- Kerberos для доменной аутентификации Windows;
- Kerberos для Linux;
- синхронизации пользователей с LDAP/AD;
- утилите синхронизации ОШС с AD.

Для ответов по AD/LDAP/Kerberos собирай:

- ОС серверной части;
- способ аутентификации;
- домен и доверенные зоны;
- где живут пользователи и группы;
- как синхронизируются роли и оргструктура;
- есть ли reverse proxy/SSO;
- текст ошибки входа.

В актуальном описании `POST /api/security/Login` сервер может определить способ проверки логина и пароля автоматически; при включённой 2FA сессия требует отдельного `TwoFactorLogin`. Не предполагай единый способ входа для всех инсталляций.

## Информационная безопасность

Для рекомендаций по ИБ не ограничивайся чек-листом. Привяжи меры к объектам Vitro-CAD:

- пользователи и группы;
- роли;
- уникальные права на СХД;
- аудит запросов;
- резервные копии;
- политика хранения файлов и версий;
- доменная аутентификация;
- доступ внешних интеграций к REST API.

## Релизы

На главной странице справки есть история изменений компонентов:

- Vitro-CAD 2024.1;
- Vitro-CAD 2025.1;
- Vitro-CAD 2026.0;
- Vitro-CAD 2026.1.

Если пользователь спрашивает о конкретной версии, открой релизную страницу и сверь дату/номер сборки. Не отвечай по памяти на "что нового в последнем релизе".

## Диагностика

Для эксплуатационных ошибок используй общий порядок:

1. Зафиксировать модуль и сценарий.
2. Получить точное время, пользователя, ID элемента/процесса/файла.
3. Проверить профильный раздел справки.
4. Для автоматизации проверить Elsa Faulted и `InnerException`.
5. Для API проверить HTTP status, endpoint, payload, correlation/request id.
6. Для доступа проверить права пользователя, группы, роли, уникальные разрешения, `project_scope`.
7. Для файлов проверить клиент, блокировки, версии, размер файла, путь СХД.
8. Для Revit проверить версию плагина, версию Revit и тип операции.
