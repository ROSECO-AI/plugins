# Установка

Для начинающего пользователя рекомендуем поручить техническую часть агенту по
[готовому промпту](PROMPT_FOR_AGENT.md). Пользователь сообщает публичный URL портала
и сам вводит вебхук в своём терминале. Вход в Битрикс24 и коды подтверждения также
выполняет пользователь.

## 1. Подготовка

Нужны Python 3.10+ ([официальная загрузка](https://www.python.org/downloads/)) и
Codex CLI с командами `plugin` и `mcp`. Агент проверяет их наличие и `--help`.
Он не устанавливает случайные одноимённые пакеты из сторонних каталогов.

Для установки плагина:

```text
codex plugin marketplace add ROSECO-AI/plugins --ref main
codex plugin add bitrix24-local-mcp@roseco-ai-plugins
codex plugin list
```

Начните новый чат с установленным плагином. Агент найдёт `runtime/install.py` внутри
плагина. Можно также скачать исходники [репозитория](https://github.com/ROSECO-AI/plugins)
через Code → Download ZIP, распаковать и открыть папку `bitrix24-local-mcp`.

## 2. Развёртывание локального сервера

Команды ниже выполняются из папки `bitrix24-local-mcp`.

macOS/Linux:

```sh
python3 runtime/install.py
```

Windows PowerShell:

```powershell
py -3 runtime/install.py
```

Если `py` отсутствует, агент проверяет `python --version` и использует найденный
Python 3.10+. Установщик регистрирует абсолютный `sys.executable`, поэтому различия
между `python`, `python3` и `py` не мешают последующему запуску.

Если Codex CLI не в PATH, передайте `--codex` с его найденным абсолютным путём.
Если имя `bitrix24-local` уже занято другим подключением, установщик остановится
до изменений. Для отдельной проверки добавьте `--server-name bitrix24-local-new`.
`--prepare-only` разворачивает код без регистрации в Codex.

Установщик печатает пути `server`, `config`, `python`. Они используются в следующих
командах; никаких секретов в этом выводе нет. По умолчанию настройки:

| Система | Папка |
| --- | --- |
| macOS/Linux | `~/.config/bitrix24-local-mcp/` (или `XDG_CONFIG_HOME`) |
| Windows | `%APPDATA%\bitrix24-local-mcp\` |

Сервер лежит в `runtime/bitrix24_mcp_server.py` внутри этой папки. Настройки —
`config.json`. Обновление плагина не меняет их; для обновления runtime повторите
установщик с тем же именем, конфигурацией и интерпретатором.

## 3. Получение и безопасный ввод вебхука

Сначала используйте подходящий существующий входящий вебхук. Если его нет, следуйте
[официальной инструкции](https://apidocs.bitrix24.ru/local-integrations/local-webhooks.html):
раздел Разработчикам → Другое → Входящий вебхук (названия разделов могут меняться).
Выдайте только нужные права: например, задачи и пользователи; CRM/диск — по задаче.
Ограничения подписки, создания вебхуков и прав пользователя определяет ваш портал.

В **своём обычном терминале** запустите команду с реальными путями из шага 2:

macOS/Linux:

```sh
"<путь-python>" "<путь-server>" --configure --portal https://portal.example.org
```

Windows PowerShell:

```powershell
& "<путь-python>" "<путь-server>" --configure --portal https://portal.example.org
```

Замените адрес примера своим публичным URL. Вебхук вставляется только в скрытый
запрос терминала. Введённые символы не отображаются. Секрет не вводится в командную
строку, чат или аргументы инструментов агента. На Windows убедитесь, что к папке
настроек нет доступа у посторонних пользователей (Свойства → Безопасность).

Повторная `--configure` заменяет выбранное подключение и выключает запись.
Для нескольких порталов используйте отдельные `--config` и `--server-name` при
установке; далее передавайте тот же `--config` во всех командах настройки и проверки.
Переменная `BITRIX24_WEBHOOK_URL` поддерживается для управляемого окружения и имеет
приоритет над файлом; секрет из другого домена блокируется проверкой portal.
Автоматического чтения `.env` нет. `config.example.json` — только пример структуры.

## 4. Проверка чтения

Запустите тем же Python развёрнутый `server` с `--check`. Проверяется `profile`,
вывод содержит только факт успеха и портал. `--status` показывает локальную настройку
и разрешённые методы чтения. Для проверки в Codex переподключите MCP или начните
новый чат после перезапуска клиента, если он не обновляет серверы автоматически.

Агент проверяет появление семи инструментов, текущего пользователя и чтение одной
задачи, если доступны нужные права. Пустой список задач не означает сбой авторизации.
Статус «установлен» не равнозначен успешному чтению. Запись для теста не нужна.

Дополнительно можно подключить официальный справочник API:

```text
codex mcp add b24-dev-mcp --url https://mcp-dev.bitrix24.tech/mcp
```

Если он уже подключён, повторно не добавляйте. Справочник не требует вебхука и не
получает доступ к порталу. [Официальная инструкция](https://apidocs.bitrix24.ru/ai-tools/mcp.html).

## 5. Когда нужны изменения в портале

По запросу пользователя запустите развёрнутый сервер с `--enable-writes` (тем же
Python, с тем же `--config`, если он нестандартный), затем переподключите MCP.
Обратная команда — `--disable-writes`. Это включает возможность, но не одобряет
все будущие действия. Оставьте подтверждения клиента для `bitrix24_write_method`,
`bitrix24_create_task` и `bitrix24_add_task_comment`. Конкретная настройка зависит
от версии клиента; агент должен проверить её по официальной справке.

После отправки сообщения с неопределённым результатом нельзя повторять его вслепую:
сначала проверьте, не появилось ли оно в портале. Встроенных повторов записи нет.

## Удаление

`codex mcp remove bitrix24-local` удаляет регистрацию (укажите своё имя, если другое).
Удаление плагина само по себе не удаляет отдельно установленный сервер и секрет.
Для полного удаления удалите выбранную папку конфигурации и отзовите соответствующий
вебхук, если он больше нигде не используется. Не удаляйте общий вебхук других интеграций.
