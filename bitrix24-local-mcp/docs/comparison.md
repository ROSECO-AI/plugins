# Локальный и официальный MCP: что именно различается

Проверено по коду локального коннектора и официальным источникам 27 ноября 2026 года.
Это сравнение архитектур. Подключение к официальному hosted MCP с учётной записью
пользователя и парный прогон одинаковых задач в этой проверке не выполнялись.

## Три разных компонента

| Компонент | Что предоставляет |
| --- | --- |
| Официальный `b24-dev-mcp` | Справку по REST API; не выполняет запросы к порталу |
| Официальный hosted MCP `mcp.bitrix24.tech` | Набор инструментов для действий с данными через OAuth/токен |
| Этот `bitrix24-local` | Локальный stdio-сервер, вызывающий REST API через личный входящий вебхук |

Источники: [справочник MCP](https://apidocs.bitrix24.ru/ai-tools/mcp.html),
[подключение внешнего AI](https://helpdesk.bitrix24.ru/open/26952788/).

## Откуда берётся гибкость локального коннектора

В [нашем коде](../runtime/bitrix24_mcp_server.py) универсальный инструмент принимает
имя REST-метода и объект параметров. Специализированная MCP-обёртка для каждого нового
сценария не нужна. Агент может прочитать официальную справку и составить последовательность
REST-вызовов. Например, `crm.item.list` используется для элементов смарт-процесса,
`tasks.task.history.list` — истории задачи, `disk.folder.getchildren` — содержимого папки.
Примеры требуют соответствующих прав и доступности метода на конкретном портале;
это не заявление, что все эти сценарии проверены на всех порталах.

Официальный hosted MCP даёт агенту инструменты, которые сервис публикует через
`tools/list`. Документация описывает задачи, CRM, структуру, приглашения и почту,
и предупреждает, что набор действий расширяется. Она не обещает универсальный доступ
ко всем REST-методам. Мы не утверждаем отсутствие конкретного инструмента без live
проверки: у разных подключений могут отличаться доступы и видимый набор инструментов.

## Почему одна и та же задача может не выполниться

| Наблюдение | Возможная причина | Что проверять |
| --- | --- | --- |
| Нет нужной команды | Метод REST не представлен инструментом или инструмент не включён в клиенте | Фактический tools/list, отключённые инструменты, документация метода |
| Команда есть, ошибка доступа | Другой пользователь, разрешения подключения, права на объект | Пользователь/портал, код ошибки, scope и объектные права |
| Подключение вообще не работает | Авторизация, запрет администратора, подписка, транспорт | MCP handshake, токен/OAuth, настройки портала и ответ сервера |
| Объектов меньше ожидаемого | Фильтр, видимость, пагинация | Параметры и next/total; доступ того же пользователя |
| Агент не пробует доступную операцию | Инструкция плагина, контекст, выбранная модель или отсутствие справки | Видимые инструменты и фактические вызовы, а не только ответ агента |

Без запроса, списка инструментов и текста ошибки нельзя приписать сбой одному лишь
официальному серверу. Название плагина также не определяет его реализацию: перенос
пакета с URL hosted MCP не переносит исходный Python-сервер, webhook и настройки.

## Сравнение

| Параметр | Локальный ROSECO MCP | Официальный hosted MCP |
| --- | --- | --- |
| Выполнение | Python на компьютере пользователя | Инфраструктура Битрикс24 |
| Доступ | Входящий вебхук своего портала | OAuth или токен MCP |
| Расширение сценариев | Вызов подходящего REST-метода; код можно доработать | Опубликованный сервисом набор инструментов |
| Документация | Отдельный b24-dev-mcp или официальный сайт | Наличие подсказок зависит от инструмента |
| Обслуживание | Обновления локального кода, Python и настроек | Обновления сервиса на стороне разработчика |
| Права | Scope вебхука и права создавшего его пользователя | Права авторизованного пользователя и подключения |
| Транспорт | stdio между агентом и процессом; HTTPS до портала | Streamable HTTP до сервиса |

## Ограничения нашего решения

Универсальный инструмент не расширяет права пользователя. Некоторые REST-методы
требуют контекста приложения и не поддерживают входящий вебхук. Также действуют
ограничения тарифа, доступности API и частоты запросов. REST3 и приём событий не
реализованы. [Официальная документация вебхуков](https://apidocs.bitrix24.ru/local-integrations/local-webhooks.html).

В версии 1.0.0 неизвестные методы требуют включённой записи; это консервативная
классификация, а не предел REST-возможностей. `batch` отключён. Результаты до 8 MiB,
входные сообщения до 1 MiB; превышение даёт явную ошибку. Каждая страница запрашивается
отдельно, автоматической полной выгрузки нет. Запись не повторяется автоматически.

Новый сервер сохраняет `next`, `total` и `time`. В исходном локальном прототипе
возвращался только `result`: поэтому прототип мог терять признак следующей страницы.
Новая версия устраняет это ограничение, но агент всё равно должен обработать страницы.

Конфигурация создаётся без права записи. После включения записи подтверждения
конкретных действий обеспечивает клиент и рабочие инструкции. Сами аннотации MCP
не являются серверным механизмом проверки согласия человека. [Спецификация MCP](https://modelcontextprotocol.io/specification/2025-06-18/server/tools).

Локальный процесс не означает локальную AI-модель и не обезличивает ответы API.

## Об открытых исходниках Битрикс24

У разработчика есть [templates-mcp](https://github.com/bitrix24/templates-mcp) —
шаблон для построения своего сервера. Это отдельный продуктовый артефакт. Список
его инструментов нельзя выдавать за проверенный список hosted MCP. Репозиторий
[mcp-rest-doc](https://github.com/bitrix24/mcp-rest-doc) описывает MCP документации.

## Формулировка для демонстрации

> Мы подготовили локальный коннектор к REST API Битрикс24. Его универсальный
> инструмент позволяет агенту строить сценарии из документированных API-методов,
> не ожидая отдельной MCP-команды для каждого случая. Каждый пользователь подключает
> свой портал и свои права. На мероприятии демонстрируем проверенные сценарии;
> универсальность не означает доступ ко всем функциям без ограничений.

Для доказательного сравнения используйте один портал, одного пользователя и
одинаковую задачу. Сохраните без секретов tools/list, вызванный метод, фильтр,
пагинацию и код ошибки обеих реализаций. Публикуйте только обезличенные результаты.
