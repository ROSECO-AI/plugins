# Битрикс24 — локальный MCP

Локальный коннектор ROSECO AI для работы AI-агента с REST API вашего Битрикс24.
Плагин содержит **сам Python-сервер и установщик**. Каждый пользователь подключает
свой портал через свой входящий вебхук. Данные и доступы других пользователей в
пакет не входят. Версия **1.0.0**, лицензия MIT.

## Установка для начинающего

Установите плагин из каталога ROSECO AI в Codex и попросите агента:

> Настрой локальный MCP для моего Битрикс24 по инструкции плагина. Сам выполни
> техническую подготовку; спроси только адрес портала и необходимые действия для
> безопасного ввода вебхука. Проверь чтение.

Если каталог ещё не подключён, команды для агента или терминала:

```text
codex plugin marketplace add ROSECO-AI/plugins --ref main
codex plugin add bitrix24-local-mcp@roseco-ai-plugins
```

## Что получает агент

| Инструмент | Возможности |
| --- | --- |
| `bitrix24_status` | Локальная диагностика, режим записи и список проверенных методов чтения |
| `bitrix24_current_user` | Чтение текущего пользователя (`user.current`) |
| `bitrix24_call_method` | Проверенные методы чтения REST API: задачи, CRM, диск, чаты и другие |
| `bitrix24_find_tasks` | Поиск задач с фильтром, полями и страницами |
| `bitrix24_write_method` | Универсальный REST-вызов для изменений и методов вне списка чтения |
| `bitrix24_create_task` | Создание задачи после разрешения пользователя |
| `bitrix24_add_task_comment` | Отправка согласованного текста комментария |

Главная особенность — универсальный REST-вызов. Для нового сценария часто достаточно
найти метод в официальной справке, без добавления отдельного инструмента в сервер.
При этом требуются права вебхука, права пользователя и поддержка метода самим порталом.

Это не продукт разработчика Битрикс24. Он не гарантирует поддержку всех функций
портала и не обходит ограничения REST API, тарифа или администратора. Только
проверенные методы доступны в режиме чтения. Остальные можно вызвать через
`bitrix24_write_method` после локального включения записи; даже неизвестный метод
чтения классифицируется консервативно. `batch` отключён; REST3/OAuth-only сценарии
и приём событий не реализованы. Подробности — [сравнение](docs/comparison.md).

## Как устроено

```text
Codex → локальный Python MCP → HTTPS REST API → ваш портал Битрикс24
          ↑
     ваш локальный вебхук
```

Плагин содержит навык настройки и исходники. Установщик создаёт отдельную MCP-запись
с абсолютным путём к найденному Python. Поэтому в пакете нет автоматически запускаемого
`mcp.json` с предположением, что на каждом компьютере доступна команда `python3`.
Установка плагина сама по себе ещё не подключает портал.

Требования: локальный Codex с поддержкой stdio MCP, Python 3.10+ и доступный REST API
Битрикс24. Код использует стандартную библиотеку, без pip-пакетов. Для коробочного
портала нужны поддерживаемые REST-методы, HTTPS и доверенный сертификат; доступность
конкретной версии проверяется отдельно. Под «любым порталом» понимается совместимый
портал Битрикс24, не произвольная корпоративная программа.

[Проверки Windows/macOS/Linux](https://github.com/ROSECO-AI/plugins/actions/runs/46012964996)
прошли на Python 3.10 и 3.13: 34 теста в каждой комбинации, установка через Codex CLI,
русские пути и повторная регистрация сервера. Реальное чтение портала проверено на macOS.

## Секреты и изменения

Секрет вводится в локальном терминале со скрытым вводом; не вставляйте его в чат.
Настройки находятся вне репозитория и кэша плагина. Начальный режим — только чтение.
Включение записи и подтверждение конкретного изменения — разные действия.
Аннотации MCP помогают клиенту различать инструменты, но не заменяют его механизм
подтверждений. Не разрешайте автоматическое выполнение всех инструментов записи.

На macOS/Linux файл создаётся с правами `0600`; на Windows установлены ACL только
для текущего пользователя через `icacls`. Это локальный файл, не шифрованное хранилище.
Пакет не обещает защиты от администратора или
других процессов того же пользователя. Ошибки скрывают вебхук и сырой ответ сервера.

Локальный коннектор не анонимизирует данные и не делает облачную модель локальной:
результаты запросов передаются агенту. Передавайте только данные, разрешённые вашей
организацией для такой обработки.

## Разработка и проверка

```text
python3 -m unittest discover -s tests -v
```

На Windows используйте `py -3` вместо `python3`. CI запускает те же проверки на
Windows, macOS и Linux. Проверки используют синтетический портал и не выполняют
изменений в корпоративных системах. Статус проверок и ограничения — [CURRENT_STATE.md](CURRENT_STATE.md).

## Обновление с прежнего локального скрипта

Сначала установите новый сервер под отдельным именем (`--server-name bitrix24-local-new`),
проверьте свой портал и только затем переключайте рабочий процесс. Новый код возвращает
полный ответ REST (`result`, `next`, `total`, `time`), а прежний возвращал только `result`.
Это исправляет потерю пагинации, но скриптам, ожидающим старый формат, нужна адаптация.
Автозагрузка `.env` из текущей папки удалена: случайная папка больше не выбирает портал.
Старое подключение установщик не перезаписывает.
